# 디톡스메이트 정책 조회

## 기준 문서

- 위키: https://www.notion.so/3d7ad7a38ce58031804dd69373f82a71
- 문서 DB: https://www.notion.so/04b8dff159e44753960b2d950ef6c5f5
- 데이터 소스: `0656dd97-8a58-47c1-84f0-edea13a3ce31`

팀이 최근 합의한 동작의 기준은 이 DB의 현재 본문이다. 배포 상태, 코드, 과거 대화와 같다고 가정하지 않는다. 정책이 없는 부분은 미정으로 알리고 추측으로 채우지 않는다.

## 연결부터 확인

기본 연결은 팀용 내부 연결로 인증하는 `detoxmate-notion` CLI다. 실행 전에 [CLI 조회 절차](references/notion-api.md)를 읽는다. PATH에서 명령을 찾고, 없으면 `$HOME/.local/bin/detoxmate-notion`을 확인한다. 특정 팀원의 사용자명·컴퓨터 경로를 사용하지 않는다.

토큰은 로컬 실행 명령이 보관소에서 불러온다. 토큰을 직접 출력하거나 대화·파일·명령 인수에 복사하지 않는다. `ntn login`이나 `codex mcp login notion`을 실행하지 않는다. CLI가 없거나 인증·접근이 실패하면 원인을 알린다. 다른 계정의 MCP로 조용히 전환하지 않는다. 사용자가 다른 연결 사용을 명시한 경우에만 그 연결의 실제 도구·스키마에 맞춰 작업한다.

## 읽을 문서 선택

1. 사용자가 대상 문서 링크를 줬으면 현재 본문과 소속을 확인한다. 디톡스메이트 정책의 근거로 사용할 때는 위 DB에 속하는지 확인한다.
2. 대상이 불명확하면 DB의 현재 속성을 확인하고 목록에서 후보를 고른다. 우선 필요한 정보는 문서명, 다루는 범위, 구분, 페이지 링크다. 관련 문서는 영향 범위를 살필 때 조회한다.
3. 주제나 이름으로 범위를 좁혀 조회한다. 일부 결과만 받았다면 필요한 후보를 찾을 때까지 페이지네이션한다. 일부 목록이나 검색 실패만으로 문서가 없다고 단정하지 않는다.
4. 선택한 문서는 조건과 예외를 놓치지 않도록 본문을 읽는다. 잘림·읽지 못한 하위 블록이 있으면 작업에 필요한 부분을 추가 조회한다. 목록의 요약만으로 정책을 판단하지 않는다.
5. 질문에 답하거나 변경 영향을 판단하는 데 필요한 공통 정책·관련 문서만 추가로 읽는다. 관계 링크를 재귀적으로 전부 탐색하지 않는다. 디자인 확인이 필요한 경우에만 Figma를 읽는다.

단순 조회에 템플릿과 모든 문서를 읽지 않는다. 같은 작업에서 이미 읽은 자료는 재사용하되, 다른 날이나 새 작업에서는 현재 Notion을 확인한다. DB의 템플릿은 제품 정책 문서가 아니다.

## 결과

질문에 필요한 정책과 해당 문서 링크를 간결하게 제시한다. 구현 작업이면 읽은 정책을 작업에 반영한다. 확정 정책, 미정 사항, 문서 간 충돌, 확인하지 못한 범위를 구분한다. 문서의 최종 수정일만으로 상충하는 규칙의 우선순위를 정하지 않는다. 조회 실패 시 로컬 복사본이나 과거 대화를 최신 SSOT로 대체하지 않는다.

이 Skill은 읽기 전용이다. 정책 수정이 요청되면 `update-notion-wiki`로 이어간다.
